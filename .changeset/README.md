# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works
with multi-package repos, or single-package repos to help you version and publish your code. You can
find the full documentation for it [in our repository](https://github.com/changesets/changesets).

We have a quick list of common questions to get you started engaging with this project in
[our documentation](https://github.com/changesets/changesets/blob/main/docs/common-questions.md).

## Workflow

1. Make changes on a feature branch.
2. Run `pnpm changeset` and describe the change. Pick the bump level (`patch` / `minor` / `major`) for every
   affected `@appifex/*` package. All `@appifex/*` packages are **linked** — they share a version.
3. Commit the generated `.changeset/*.md` file alongside your code change.
4. Open a PR. CI runs `pnpm check` (lint + format + typecheck + test) + `pnpm publish --dry-run` per package.
5. When the PR merges to `main`, the Changesets GitHub Action opens a "Version Packages" PR that bumps
   versions + updates CHANGELOGs. Merging that PR triggers `release.yml` to publish every package to npm
   under the `@appifex` scope with `--access public` using `NPM_TOKEN`.

## Config

- `linked: [["@appifex/*"]]` — every `@appifex/*` package bumps together (one version across the scope).
- `access: "public"` — scoped `@appifex/*` packages ship publicly on npmjs.org.
- `baseBranch: "main"` — versioning PRs and diff detection anchor to `main`.
- `updateInternalDependencies: "patch"` — bumps internal workspace dep ranges at patch level.

## Do not edit

`.changeset/*.md` (except the ones you create via `pnpm changeset`) and this folder layout are managed by the
Changesets CLI and the Changesets GitHub Action.
