    if (resolvedBaasProvider === 'firebase' && !canSkipPhase('firebase_provision')) {

      const { runFirebaseProvision } = await import('@appifex/baas')

      // Check if GoogleService-Info.plist already exists (idempotency guard — D-05)
      const plistPath = join(outputDir, 'GoogleService-Info.plist')
      const plistExists = await runner.exists(plistPath).catch(() => false)

      // Phase 4 (FIRE-05): lint runs inside runFirebaseProvision before rules are deployed (D-13).
      // Phase 4 (FIRE-04): plist download (firebase apps:sdkconfig) also runs inside runFirebaseProvision
      //   when plistExists is false. If the download exits non-zero, runFirebaseProvision throws
      //   ProvisionError — do NOT catch it here; let it propagate as CliError to the pipeline runner.
      const result = await runFirebaseProvision({
        outputDir,
        runner,
        config: dtcConfig,
        baasSchema: baasSchema!,
        plistExists,
      })

      if (result.skipped) {
        checkpoint.savePhase(checkpointRunId, 'firebase_provision', {
          status: 'skipped',
          reason: 'GoogleService-Info.plist already present',
        })
        emit('firebase_provision', 'skipped', 'skipped (checkpoint complete)')
      } else {
        // Emit gitignore tip per UI-SPEC.md copywriting contract
        emit(
          'firebase_provision',
          'running',
          chalk.dim(
            'Tip: add GoogleService-Info.plist to your project .gitignore to avoid committing secrets.',
          ),
        )

        if (result.collectionsSeeded !== undefined && result.collectionsSeeded > 0) {
          emit(
            'firebase_provision',
            'running',
            `Seeded ${result.collectionsSeeded} empty collection(s)`,
          )
        }

        checkpoint.savePhase(checkpointRunId, 'firebase_provision', {
          status: 'completed',
          completedAt: new Date().toISOString(),
          projectId: result.projectId,
          iosAppId: result.iosAppId,
          plistPath: result.plistPath,
          collectionsSeeded: result.collectionsSeeded,
        })

        emit('firebase_provision', 'completed', 'Firebase provision complete')
      }
    } else if (resolvedBaasProvider === 'firebase' && canSkipPhase('firebase_provision')) {
      emit('firebase_provision', 'skipped', 'skipped (checkpoint complete)')
    }

| ProvisionError / SecurityLintError propagation | Errors must propagate as CliError subclasses — not swallowed, not turned into process.exit calls; this includes ProvisionError from plist download failure |
| Checkpoint state → idempotency decision | plistExists check must accurately reflect disk state; stale checkpoint cannot allow re-deployment of rules |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05-01 | Information Disclosure | DtcConfig.firebase.serviceAccountKeyPath in phase error output | mitigate | phase error messages use String(err) which shows the ProvisionError message, not the config object; serviceAccountKeyPath is not stringified into error messages by the pipeline handler |
| T-04-05-02 | Repudiation | firebase_provision checkpoint not saved on plistExists=true path | mitigate | Both the skipped-because-plist-exists path AND the idempotency-via-checkpoint path save a checkpoint row; canSkipPhase correctly returns true on resume |
| T-04-05-03 | Denial of Service | baasSchema being undefined when firebase_provision runs | mitigate | The `!` non-null assertion is guarded by the `resolvedBaasProvider === 'firebase'` check; baas_schema phase always runs before firebase_provision in PHASE_ORDER; if baas_schema was skipped, baasSchema is rehydrated from previousContext |
| T-04-05-04 | Elevation of Privilege | SecurityLintError bypassed by pipeline catch/swallow | accept | Pipeline's top-level catch in runPipeline rethrows CliError subclasses; ProvisionError and SecurityLintError both extend CliError; they cannot be swallowed by the existing error handling |
| T-04-05-05 | Denial of Service | ProvisionError from plist download silently swallowed | mitigate | Task 1 action explicitly prohibits try/catch wrapping of runFirebaseProvision; ProvisionError propagates as CliError to the pipeline's top-level handler which surfaces it to the user |
