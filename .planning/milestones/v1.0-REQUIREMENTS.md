## v1 Requirements (Final State)

### Open-Source Release Readiness

- [x] **REPO-01**: Repo hygiene landed — `LICENSE` (MIT), `README.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, and GitHub issue/PR templates under `.github/`
- [x] **REPO-02**: Secret scanning clean — `gitleaks` runs in pre-commit and in CI; historical repo scanned
- [x] **REPO-03**: Conventional Commits + Changesets — `@changesets/cli` configured, commitlint enforces Conventional Commits, every PR requires a changeset entry
- [x] **REPO-04**: Public documentation — README with install + quickstart; `docs/` with getting-started, CLI reference, and contributing guide
- [x] **NPM-01**: Workspace packages rebranded under `@appifex/*` scope; `package.json` publish metadata set for every published package
- [x] **NPM-02**: GitHub Actions release workflow publishes to npm via `changesets/action` on merge to `main`
- [x] **FLOW-01**: git-flow branching live — `main` and `develop` protected; branch protection rules enforced
- [x] **GATE-01**: Required CI check — lint + typecheck + `vitest run`
- [x] **GATE-02**: Required CI check — `dtc` pipeline E2E smoke
- [x] **GATE-03**: `CODEOWNERS` in place; branch protection requires ≥1 approving review
- [x] **GATE-04**: PR check — every PR must include a changeset entry

### Foundation Hardening

- [x] **FOUND-01**: `bin/dtc` resolves correctly on every install (replace absolute symlink with relative/shim)
- [x] **FOUND-02**: Token estimator reflects real Swift token density (`CHARS_PER_TOKEN` corrected from 4 to 3); fix loop reserves at least 30% budget for remediation
- [x] **FOUND-03**: Pipeline hard-fails on EPIPE during LLM I/O
- [x] **FOUND-04**: Pipeline wrapped in subprocess boundary so `process.exit(...)` cannot kill the MCP host process

### Setup & Diagnostics

- [x] **SETUP-01**: `dtc setup --full` wizard captures Apple ASC key, Firebase project selection, LLM provider key, and Google/Apple OAuth client IDs
- [x] **SETUP-02**: `CredentialRegistry` runs in `preflight.ts` and fails fast with per-credential status
- [x] **SETUP-03**: `dtc doctor` checks presence and validity of `firebase-tools` CLI, service-account JSON, and ASC API key file
- [x] **SETUP-04**: Wizard can create a new Firebase project and auto-link the iOS app, downloading `GoogleService-Info.plist` *(code-verified; live run pending)*

### Firebase Integration

- [x] **FIRE-01**: Generated SwiftUI apps use `@UIApplicationDelegateAdaptor` with Firebase-configured `AppDelegate`; Firebase SDK pulled via SPM only
- [x] **FIRE-02**: Generated auth supports email/password, Sign In with Apple (hashed-nonce), and Google Sign In (REVERSED_CLIENT_ID URL scheme)
- [x] **FIRE-03**: Generated data layer exposes typed Firestore `Codable` models, realtime listeners, and offline caching
- [x] **FIRE-04**: `firebase_provision` pipeline phase: idempotent, creates/links project, downloads plist, deploys rules *(code-verified; live provisioning run pending)*
- [x] **FIRE-05**: Security lint blocks ship on rules allowing cross-user reads or missing deny-all default

### TestFlight / Distribution

- [ ] **TF-01**: `testflight_upload` pipeline phase archives and uploads via `xcrun altool` with ASC REST JWT *(code-verified Phase 5; live TestFlight run not performed)*
- [ ] **TF-02**: XcodeGen `project.yml` mutated via `js-yaml` *(code-verified Phase 5; live run not performed)*
- [ ] **TF-03**: Archive pipeline injects release hygiene: encryption flag, build-number guard, dSYM format *(code-verified; live run not performed)*
- [ ] **TF-04**: Uploaded builds auto-assigned to TestFlight internal testing group *(code-verified; live run not performed)*

### Validation & Fix Loop

- [x] **VAL-01**: Maestro E2E golden-path flow on simulator against real dev Firebase project before upload *(code-verified; live Maestro run pending)*
- [x] **VAL-02**: Fix loop selects context by modified-screens / failing-test locality
- [x] **VAL-03**: LLM fix loop uses Anthropic structured outputs beta
- [x] **VAL-04**: Validation gate: hard-fail (security lint + semgrep) vs soft-fail (Maestro + unit tests + `--skip-validation-gate`)

### Design Adapter Parity

- [x] **DESIGN-01**: Pencil adapter handles pathological layer names via shared sanitization
- [x] **DESIGN-02**: Figma REST and Figma-Make adapters pass the same layer-name sanitization fixtures
- [x] **DESIGN-03**: Stitch adapter passes the same layer-name sanitization fixtures
- [x] **DESIGN-04**: Golden-fixture IR consistency test: one reference design round-trips through all four adapters

### MCP / Agent Surface

- [x] **MCP-01**: MCP server exposes `dtc_firebase_provision` and `dtc_testflight_upload` tools
- [x] **MCP-02**: MCP server exposes `dtc_get_pipeline_status` with checkpoint + phase state
- [x] **MCP-03**: Pipeline writes `.dtc-manifest.json` listing generated files; user-edited files detected and preserved

### Observability

- [x] **OBS-01**: Terminal UI surfaces live token + USD cost per phase and run-total summary
- [x] **OBS-02**: Each run produces a structured `.dtc-report` with per-phase status
- [x] **OBS-03**: Failed runs export a zippable debug bundle
